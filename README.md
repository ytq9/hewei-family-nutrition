# 禾味日历

一款面向家庭的响应式菜单、菜谱与营养记录 PWA。它把“今天吃什么、谁参与用餐、摄入是否合理、需要采购什么”放进同一套可追踪流程，在手机、平板和电脑上均可使用。

**在线体验：** [hewei-family-nutrition.spiffy-aphid-8940.chatgpt.site](https://hewei-family-nutrition.spiffy-aphid-8940.chatgpt.site)

> 当前版本是无需账号和数据库的纯静态应用。菜单及健康数据仅保存在当前浏览器，适合体验、个人使用与前端工程展示。

## 项目背景

家庭成员的饮食需求、参与餐次和实际份量各不相同，传统菜单通常只能记录菜名，难以同时完成营养计算、个人摄入分配和采购汇总。本项目将菜单、菜谱、成员档案与购物清单关联，并通过标准 JSON 文件解决菜谱复用和数据迁移问题。

## 核心功能

- **菜单编排：** 按日期管理早餐、午餐、晚餐和加餐，同一餐次可自由添加多道已有菜品。
- **菜谱管理：** 编辑菜名、标签、备注、食材、重量、可食比例、生熟状态、出品份数和成品重量。
- **标准文件：** 支持标准 JSON 菜谱的粘贴导入、文件导入与导出，可配合 GPT 生成后直接复用。
- **营养计算：** 计算能量、蛋白质、脂肪、碳水化合物、膳食纤维、钠、钙、铁、钾及维生素 C/D。
- **多人分配：** 为每餐设置参与成员和用餐时间，支持按份数或成品克数记录个人摄入。
- **家庭档案：** 编辑家庭名称与成员档案，记录体重、体脂、血压和血糖趋势。
- **采购联动：** 根据指定日期范围内的菜单重新生成采购清单，合并同类食材并换算常见单位。
- **本机数据：** 自动保存数据，支持完整 JSON 备份的导入与导出。
- **移动体验：** 手机优先的响应式布局、底部导航、大触控区域和 PWA 主屏幕安装。

## 关键问题与解决方案

| 问题 | 解决方案 |
| --- | --- |
| 同一道菜由多人以不同份量食用 | 同时支持“份数”和“成品克数”两种分配模式，并校验总分配量 |
| 部分食材缺少微量营养数据 | 使用 `null` 表示缺失值；任一相关食材数据缺失时显示“数据不完整”，不按 0 计算 |
| 修改菜谱可能改变过去的摄入结果 | 已确认餐食保存营养快照，后续编辑菜谱不会追溯覆盖历史记录 |
| 菜单修改后采购数量容易失真 | 采购清单从选定日期范围的菜单重新汇总，合并同类食材并统一 g/kg、ml/L |
| AI 生成的菜谱文本难以稳定复用 | 使用 Zod 校验标准 JSON 结构，拒绝可执行文本、错误格式和非法营养数值 |
| 不使用付费数据库仍需保存与迁移数据 | 使用 `localStorage` 自动保存，并提供完整 JSON 备份导入导出 |

## 营养计算规则

```text
食材营养 = 每 100g 营养 × 食材重量 × 可食比例 ÷ 100
按份摄入 = 菜品总营养 ÷ 出品份数 × 实吃份数
按克摄入 = 菜品总营养 ÷ 成品重量 × 实吃克数
```

- 油、盐和调料作为普通食材参与计算。
- 缺失营养数据保持为未知状态，不使用 0 代替。
- 克数分配必须先填写菜品成品重量。
- 页面结果用于日常记录与营养参考，不构成诊断或治疗建议。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev:static
```

构建纯静态文件：

```bash
npm run build:static
```

执行验证：

```bash
npm run lint
npm test
```

静态构建结果位于 `static-dist`，该目录属于生成产物，不提交到 Git。复制 `.env.example` 为 `.env.local` 后，可以按需修改正式站点地址。

## 数据与隐私

- 应用不需要 CloudBase、数据库、账号或 API Key。
- 菜单、菜谱、成员、体征和购物清单仅保存在当前浏览器。
- 不同设备不会自动同步；更换设备或清理浏览器数据前应导出备份。
- 静态网页不能安全保存混元视觉等云服务密钥，因此不提供拍照识别或云端 AI 识别。
- 演示食材保留 USDA FoodData Central 来源编号和版本，不批量复制版权状态不明确的数据源。

## 当前边界与后续方向

- 当前不支持多人实时协作和跨设备自动同步。
- 当前不提供疾病诊断、治疗建议、库存管理或自动估重。
- 后续可在独立后端中增加登录、家庭邀请、加密同步和服务端权限控制。
